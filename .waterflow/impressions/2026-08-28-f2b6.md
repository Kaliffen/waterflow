Emitting before any commit exists stays legal; `unborn` becomes a defined value
of `revision` that `recall` always reports as freshness unknown.

Nine of eleven records and all ten items in the crowd-sim store carry
`revision: unborn`, written by hand as an ad-hoc comment because the contract had
no value for the case. This repository then reproduced the same failure inside
the diff meant to fix it: e6b4 was emitted against an uncommitted tree and needed
c6e3515 to close it.

Owner rejected requiring a commit before emission. That rule would be broken
every time, because the moment worth emitting at is when the work settles, not
when it is committed, and a rule that fights the workflow loses. Owner also
rejected having the proof gate refuse a record with no reachable anchor, which
turns a documentation gap into a commit failure.

Making `unborn` a defined value puts the warning where the next reader already
is. `recall` has an unreachable-anchor path and already reports such a record as
freshness unknown rather than current; `unborn` is the same case named honestly,
and it costs a row in the contract's field table.
