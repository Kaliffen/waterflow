The proof gate is the seam: it is the only executable consumer of the store, and
its fixture harness is where every structural claim about the new record kinds is
observed.

Confirmed with the owner. The gate globs one directory and reads `state`,
`revision`, `scope` and `supersedes`; `scripts/test-proof-gate.sh` runs it
against a throwaway git repository, one case per behaviour. That is enough to
observe the whole structural design: that a record asserting no verdict does not
gate a commit, that a file under the history directory is invisible, that a
relocated store still resolves.

The seam settles a design question rather than only hosting it. Because the gate
reads exactly one directory, moving spent watermarks out of it makes them
invisible with no change to the script. The exclusion chosen in 2026-08-29-a9e3
is enforced by a mechanism that already exists, which is the difference between a
convention and a structure.

Nothing is faked across it. The harness builds a real repository and runs the
real script.

**The second seam, named because it is weaker.** The contract wording, `recall`'s
steps and `land`'s new step are prose, and nothing executable can check them.
They are observed by `critique` and by the link and frontmatter checks in
check.mjs. The rejected alternative was teaching check.mjs to validate impression
frontmatter, which would put a second, weaker store parser in the repository
competing with the gate's.
