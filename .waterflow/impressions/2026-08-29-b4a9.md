The query that answers "what is unproven here" was itself unusable: it filtered
on kind alone, so it reported every subject's debts and counted paid ones as
outstanding.

Two axes, both joined. Fixed at d9ec671.

**The corroborated defect.** An observation that has been promoted is named in
the `supersedes` of the fact that promoted it. A list that does not exclude
superseded records therefore reports as unproven precisely the thing that was
proved -- the index-that-lies failure the same file forbids three sections
earlier. It skipped the subject filter too, contradicting its own sentence about
what *this subject* would have to prove.

**Found by spec.** Thirty-two of the thirty-four records in this store carry no
`kind`, because they predate it. The new report grouped by kind and therefore
left almost all of a real store ungrouped -- a design checked against the store
it describes rather than against an imagined one.

**Found by standards.** Two sentences in `recall` restated what an observation
is and how it is promoted. `recall` reads and does not write, so it cannot
promote anything: by the rule-homes test the text lost no instruction, only a
restatement.

**Withheld deliberately.** Both axes noted the contract describes a history
directory nothing writes. That mover is the consolidation slice. Rather than
build it early the contract now says plainly that nothing writes it yet and
names the step that will, which is the honest form of a forward reference.

**Carried forward, not fixed.** Every query in the store's documentation
hardcodes `.waterflow/impressions/` while the proof gate honours a relocated
store through config. Spec is right that this diff adds a fifth instance to a
pre-existing four. It is a real defect and it is not this slice's.
