for, but most of what both axes reported was true of an earlier state of the
tree than the one they were asked to review.

Supersedes 2026-08-28-8a3c. Two axes, dispatched in parallel, both joined.

**Verified rather than argued.** Spec asked whether the new check actually
detects the field case, which is the right question and was answerable. Run
against waterflowtest2's c7d1 -- anchor c5e8355, three files under
src/Crowd.Sim/ -- the command names all three scope paths; run against 3c99,
which is correctly anchored, it prints nothing. The rule catches what it was
written for and stays quiet otherwise.

**The findings that stood.** Spec's reading of `land` was the valuable one: an
earlier draft re-anchored "the records this run proved", which excludes `define`,
`seam` and `slice` records and therefore every one of the five mis-anchored
records in the field store. The rule would have repaired none of the cases that
motivated it. It now covers every record and item in the work being landed.

**Most findings were stale.** Both axes reported against text that had already
been revised: a two-sentence gist that is one sentence, a `recall` step 5 with
two cases that has three, a subject collision between a `prove` record and
`field-proof` that does not exist, an unnumbered section between steps 4 and 5
that sits inside step 4. Each was a real defect at some point during the session
and each was fixed before they read it.

That is worth recording because it is a topology finding, not a review finding.
A subagent briefed with a diff command reads the tree when it gets there, and a
long session repairs itself underneath. The brief named a fixed point and the
agents honoured it; what drifted was everything the fixed point does not pin.
Dispatching a review of a working tree that is still being edited buys reports
about a state nobody can reproduce. Either the tree is quiet while the review
runs, or the review is given a revision and not a path.
