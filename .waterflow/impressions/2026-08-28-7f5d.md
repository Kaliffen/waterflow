Waterflow's own repository keeps an impression store at .waterflow/ and builds
itself through the flow.

Settled by the owner. The store is a factory surface: it versions alongside the
code and does not ship to consumers, who get `skills/**` and the manifests. It
does not violate the distribution boundary because `.waterflow/` is a convention
the shipped skills already assume in any repository, not this repository's
layout leaking into them.

Live reads work mid-session: the store is grepped when `recall` runs and a
reference is loaded when its dial comes into play. Only the skill list is frozen
at session start, which is why changes here stayed inside the existing eleven
model-invoked skills.
